# 客户端（`android/`，网页版同理）

面向开发与排障。**界面不解释技术**：App 的设置页只留一句话和两个输入框，技术细节都在这里。

相关文档：插件端见 [plugin-server.md](plugin-server.md)，Android 实现细节与构建命令见 [android/README.md](../android/README.md)。

## 1. 产品原则

- 打开只有一只鲸鱼，点一下进入通话。没有输入框、没有技术参数、没有音色选择。
- **通话是常驻的**：说一句、等回复、接着说，全程不用碰屏幕；鲸鱼朗读时直接开口不会打断，你说的话照样识别、排队等它说完。
- 设置页最多三样东西：地址、配对码、连接状态。够用即可，不写引擎名、不写接口路径、不写模型名。
- 所有技术解释放文档；界面只回答「连上了吗」「在听吗」「在说吗」。
- 错误提示一句人话（「配对码不正确」「网络异常，请确认和电脑在同一网络」），不暴露状态码与堆栈。

## 2. 页面结构

| 页面 | 内容 |
| --- | --- |
| 主屏 | 形象（内置 Deepy 素材包，铺满整屏）、一句话状态、单行字幕、通话按钮（麦克风 / 挂断）、右上角设置 |
| 设置（底部弹层） | 标题 + 「连接桌面端的小鲸鱼，就能开口聊天。」、桌面端地址、配对码、搜索 / 连接、连接状态点、搜索到的设备、结果提示 |

状态映射：

| 状态 | 界面 |
| --- | --- |
| 未通话 | 「轻触鲸鱼开始通话」，蓝色麦克风按钮 |
| `LISTENING` | 「在听你说…」，红色挂断按钮 |
| `THINKING` | 「Deepy 正在想…」，此时开口**不会**打断，识别结果照样发给插件排队 |
| `SPEAKING` | 「Deepy 在说话…」，逐句流式出声；朗读不会被打断，新说的话排在后面播 |
| 失败 | 一句人话；**通话不退出**，继续听，只有麦克风起不来才结束通话 |

**形象只有内置的 Deepy**：素材随 APK（`app/src/main/assets/packs/deepy/`），首次启动复制到 `filesDir`，删了会自动补回、不能删也不能改名；代码绘制的旧形象（Eva）已整体删除。形象层是根 `Box` 的第一层 `Modifier.fillMaxSize()`，字幕与通话按钮浮在它下方。

播哪一帧不看 `emotion`，看通话阶段：待机 `sleeping`、通话中 `happy`、思考 `typing`、说完先 `notification`（包内 idle）两秒再回 `happy`。

**字幕只占一行**：`captionTail()` 压掉换行、按整句截尾，`maxLines = 1`；逐字节奏由播放头驱动（`captionChars` ← `AudioTrack.playbackHeadPosition` 落在哪一句、句内比例），所以是「声音走到哪，字吐到哪」，不会先打完字等声音。

「已连接」只在 `/api/health` 校验通过后点亮（`reachable`），填过地址不算连接。

底部的副标题只在按钮那一行显示，主屏中间不再重复写状态。

## 3. 与插件的协议

**0.11.0 起只有一条连接**：`ws://<host>:8787/xiaozhi/v1/`（小智协议，完整定义见 [`ws-protocol.md`](ws-protocol.md)）。
HTTP 只剩「连接设置」里的探活，识别 / 对话 / 合成全部在 WS 上：

| 用途 | 通道 | 客户端做的事 |
| --- | --- | --- |
| 发现/连通 | `GET /api/health` | 扫本机 /24 的 8787，`ok && pluginLoaded` 视为可用；只在设置页「连接」时用一次 |
| 握手 | `hello` | 声明上行 `pcm16/16000/60ms`，收服务端 hello 的下行参数（24 kHz） |
| 上行 | `listen start` + PCM 帧 + `listen stop` | 本地 VAD 切出一句就整段推上去（16 kHz / mono / s16le） |
| 用户字幕 | `stt` | 显示「你：…」 |
| 情绪 | `llm.emotion` | 只进状态，不决定播哪帧（形象按通话阶段播） |
| 回复音频 | `tts start` / `sentence_start` / 二进制帧 / `tts stop` | 每句一到就把字幕切成该句，音频直接写 `AudioTrack` |

- 鉴权：握手头 `Authorization: Bearer <PIN>`；LAN 不通就直接 401，不会「连上再踢」。
- `device-id` 首次生成后持久化，握手头 `Device-Id` 带上，服务端按它选角色（`bindings`）。
- 断线：0.5 → 1 → 2 → 4 → 8 → 10 s 退避重连，状态栏显示「连接断开，正在重连…」，重连后继续可用。
- 播放：`AudioTrack` `MODE_STREAM` 边收边播（`voice/StreamingPlayer.kt`），不再落 mp3 用 `MediaPlayer` 整段播。

## 3.1 流式输出是怎么做到「边收边打字幕边出声」的

1. 服务端把回复**按句切开**（`。！？；` 等），一句合成完就下发 `sentence_start` + 该句音频，不等整段；
2. 客户端把音频帧直接写进 `AudioTrack`，第一句到就能出声，后面的句子还在线上合成；
3. `sentence_start` 在音频之前到达，播放器记下「这句从第几个采样开始」；字幕按
   `playbackHeadPosition` 反查当前落在哪句、句内比例多少，折算成字数 → **字跟着声音走**；
4. 收到 `tts stop` 只代表「音频发完了」，要等播放头追上已写入的采样数才回「在听你说」。

## 3.2 朗读期间用户开口怎么办

策略仍是**不打断**：

1. 朗读继续播，用户这句话照常上行，服务端排队；
2. 当前回复播完，服务端立刻开始下一轮（同一条连接内串行），中间没有重连与握手；
3. 新回复的第一句一到就切字幕，并从 0 跟着播放进度逐字。

代价是「插话即时静音」这个体验没有了，换来的是朗读不被自己的回声打断——这台 ROM 拿不到平台 AEC（`VOICE_COMMUNICATION` 早期返回全 0 采样），旧策略下经常出现 Deepy 被自己的回声说停。防自打断的两层保护还在：朗读期把音量门限抬高、要求连续有声；朗读期起步却没被判为人声的片段直接丢弃，不送识别。断句也留在手机侧正是为了这个（服务端 VAD 会把回声一起切进去）。

## 4. 为什么客户端不选音色

音色、语速、音调都由服务端定（管理页「声音」），理由与 ASR 相同：

- 客户端一换机型/ROM，本机 TTS 音色就变，体验不可控；统一在 PC 出声可复现。
- ESP32 也走同一条 `/api/tts`，三端听到同一把声音，不需要维护三套音色配置。
- 代价：手机必须连得上 PC，且 PC 能联网；首句约 2 s 出声；PC 不可达就没有语音。

如果以后要让人耳挑音色，服务端 `/api/tts` 的 `voice/rate/pitch` 参数仍在，客户端加个下拉把参数带上即可。

## 5. 构建与安装

环境与完整命令见 [android/README.md](../android/README.md)（JDK 17、Gradle 8.11.1、SDK 34、`local.properties` 写 `sdk.dir`）。

```powershell
$env:ANDROID_HOME = 'D:\Env\AndroidSDK'
Set-Location 'e:\File\Repo\dsh-android\android'
& '...\gradle-8.11.1\bin\gradle.bat' :app:assembleDebug --no-daemon
& adb install -r app\build\outputs\apk\debug\app-debug.apk
```

当前版本 `0.10.1`（`versionCode 11`，`compileSdk 35`），APK 约 25 MiB，无模型、无 native 库。

## 6. 排障

| 现象 | 检查 |
| --- | --- |
| 「连接失败，请检查地址和配对码」 | PC 与手机同一网段；Windows 防火墙放行 8787；对照管理页配对码 |
| 搜索不到设备 | `/24` 扫描只在同一子网有效；AP 隔离 / 跨网段请手填地址 |
| 能连上但没声音 | PC 是否联网（合成走 Edge 在线语音）；管理页「试听」是否出声 |
| 说话后一直「正在识别…」 | `/api/asr` 是否可达；PC 侧模型是否加载 |
| 说话完全没反应（连字幕都不刷新） | VAD 没触发。临时在 `CallSpeechInput` 打 `rms/peak/noise/thr/voiced` 日志，看门限是否高于说话峰值；环境吵会把噪声底抬高 |
| 鲸鱼说话时把自己的声音识别成一句话（自问自答） | 扬声器被当成插话（本机拿不到平台 AEC）。调高 `PLAY_MIN_THRESHOLD`、加长连续有声要求、降低外放音量；朗读期起步却未判为人声的片段应直接丢弃 |
| `adb reverse` 不生效 | 该 ROM 能建连但不转发，走同 WiFi 或 USB 共享网络 |
| 提示「配对码不正确」 | 管理页重新生成并保存，App 里同步修改 |
